# YouTube Shorts Auto-Generation Design Spec

## Overview

Automatically generate a 30-60 second vertical (9:16) YouTube Shorts video as part of the existing YOMOO daily pipeline. The Shorts picks the single most impactful news item from the daily report, generates an independent script and audio, renders a vertical video with high visual impact, and uploads it to YouTube with `#Shorts` tag.

## Goals

- Increase YouTube discoverability via Shorts algorithm
- Reuse existing infrastructure (Remotion, MiniMax TTS, YouTube OAuth)
- Fully automated — no manual intervention needed
- Non-fatal — Shorts failure should not block the main pipeline

## Content Strategy

Based on channel analytics, high-performing videos share a pattern: **AI directly affecting people's daily lives** gets 10-100x more views than niche/specialist topics. The Shorts script generation prompt should bias toward selecting news with this quality.

## Data Flow

```
Pipeline: long video YouTube upload completes
  → AI selects the most impactful news item from the report
  → Generates 30-60 second Shorts script (punchy, direct, hook-first)
  → MiniMax TTS generates audio (same voice, same config as long video)
  → Generates Shorts scenes.json (vertical layout)
  → Fetches OG image for the selected news item
  → Remotion renders 1080x1920 vertical video
  → Uploads to YouTube with #Shorts tag
```

## Component Design

### 1. Shorts Script Generator (`ai-report.ts`)

New exported function: `generateShortsScript(reportContent: string, onStatus: (s: string) => void): Promise<ShortsScript>`

**Input:** The daily report markdown content (already generated by this point in the pipeline).

**Output:**

```typescript
interface ShortsScript {
  title: string // YouTube title for the Shorts (max 60 chars, punchy)
  headline: string // Bold headline for on-screen display (max 15 chars Chinese)
  script: string // 30-60 second spoken script
  newsUrl: string // URL of the source article (for OG image fetching)
  ogImageUrl?: string // OG image URL if available in the report
}
```

**Prompt strategy:**

- Select the single most "普通人切身相关" (personally relevant to average person) news item
- Write a hook-first script: start with the most shocking fact, no intro/greeting
- No "大家好" or show branding in the script — Shorts need to grab in 1 second
- End with a CTA: "关注看更多每日AI快送"
- Generate a short, provocative headline for on-screen display (like existing thumbnails: "AI接管你的电脑了", "AI自己踩下了刹车")

### 2. Shorts Scene Generator (`scene-generator.ts`)

New exported function: `generateShortsScenes(shortsScript: ShortsScript, audioDuration: number): ShortsScenes`

**Output:**

```typescript
interface ShortsScenes {
  headline: string
  ogImageUrl?: string
  ogImagePath?: string // local path after download
  audioDuration: number
  subtitles: SubtitleLine[]
  youtubeTitle: string
  youtubeTags: string[]
}
```

Simpler than the full video scenes — no multi-scene composition. Just one continuous scene with the vertical layout.

### 3. Shorts Remotion Composition (`video/src/ShortsVideo.tsx`)

New Remotion composition registered in `Root.tsx`:

- **ID:** `ShortsVideo`
- **Resolution:** 1080x1920 (9:16)
- **FPS:** 30
- **Duration:** derived from audio length

**Components:**

- `ShortsBackground` — OG image with dark overlay, subtle zoom animation
- `ShortsHeadline` — Large bold text, fade-in with scale animation
- `ShortsSubtitles` — Bottom-aligned subtitle display, synced to audio
- `ShortsBranding` — Small YOMOO logo at top

### 4. Shorts Video Renderer (`video-render.ts`)

New exported function: `renderShorts(scenesJsonPath: string, audioPath: string, outputPath: string, options: RenderOptions): Promise<void>`

Calls Remotion CLI with:

- `--composition ShortsVideo`
- `--width 1080 --height 1920`
- Same pattern as existing `renderVideo()`

### 5. Pipeline Integration (`pipeline.ts`)

After the existing YouTube upload stage (Stage 8), add a new non-fatal stage:

```
Stage 9: Shorts Generation + Upload (if YouTube enabled)
  9a. Generate Shorts script from reportContent
  9b. Generate Shorts audio via MiniMax TTS
  9c. Generate Shorts scenes
  9d. Fetch OG image
  9e. Render Shorts video via Remotion
  9f. Upload to YouTube with #Shorts tag
```

**Non-fatal:** Entire Stage 9 is wrapped in try/catch. Failure logs a warning but doesn't affect the pipeline result.

**Pipeline step count:** `total` increases by 1 when YouTube is enabled.

### 6. YouTube Upload for Shorts (`youtube.ts`)

Reuse existing `uploadVideo()` — no new function needed. Differences in the call:

- Title: the short, punchy `shortsScript.title` (max 60 chars)
- Description: minimal — just the news headline + channel CTA + link to full episode
- Tags: add `"Shorts"` to existing tags array
- Same category (28 - Science & Technology), same privacy (public)

YouTube automatically treats videos under 60 seconds as Shorts.

## Preferences

Add `youtubeShortsEnabled: boolean` to `UserPreferences` in `preferences.ts`, default `true`. Shorts generation (Stage 9) only runs when both `youtubeEnabled` and `youtubeShortsEnabled` are true.

The renderer preferences UI should add a toggle for this setting alongside the existing YouTube toggle.

## What We Are NOT Building

- No new database tables
- No Shorts-specific thumbnail (YouTube auto-selects a frame for Shorts)
- No separate pipeline command (integrated into main pipeline only)
- No Shorts analytics (existing YouTube analytics feature already covers this)

## Error Handling

- All of Stage 9 is non-fatal (try/catch, log warning, continue)
- If OG image fetch fails, render without image (solid background with headline only)
- If TTS fails for Shorts, skip Shorts entirely
- If Shorts render fails, skip upload
- Pipeline result still reports `youtubeUrl` for the long video regardless of Shorts outcome

## Testing Strategy

- Unit tests for `generateShortsScenes()` (scene structure, subtitle handling)
- Unit tests for `renderShorts()` (CLI arguments verification, mocked)
- Integration: manual testing of full pipeline with Shorts enabled
